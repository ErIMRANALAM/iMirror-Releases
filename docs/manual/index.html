iMirror for macOS

User manual

Connect an Android device, mirror its display, and use Mac controls. This guide is designed to scroll—use the section links to jump directly to a topic.

Before you begin

  • A Mac running macOS 14 or later.
  • An Android phone or tablet with Developer options enabled.
  • A USB cable for wired setup, or a trusted Wi-Fi network shared by the Mac and Android device.

iMirror uses Android Debug Bridge (ADB). If Platform-Tools are not installed, iMirror can offer to download them from Google's official source after showing the SDK terms for your review. Java and Android Studio are not required on the receiving Mac.

Connect over USB

  1. On Android, open Settings and enable Developer options. The exact menu path varies by manufacturer.
  2. Enable USB debugging, then connect the device to your Mac.
  3. Unlock Android and approve the Allow USB debugging? prompt. If available, select “Always allow from this computer” only on a Mac you trust.
  4. In iMirror, choose the authorized device and select Start mirroring.
First connection: keep the Android device unlocked while it authorizes. If macOS asks for permission to find devices on the local network, allow it for Wi-Fi ADB discovery.

Connect over Wi-Fi

Wireless debugging is supported on Android 11 and later. Keep the Mac and phone on the same trusted network.

  1. On Android, open Developer options and enable Wireless debugging.
  2. Choose Pair device with pairing code. In iMirror, choose Connect over Wi-Fi and enter the pairing IP address, port, and six-digit code shown on Android.
  3. After pairing, connect using the separate IP address and port shown on the main Wireless debugging screen. The pairing port and connection port are different.
  4. When the device appears in iMirror, select it and start mirroring.

A USB-assisted Wi-Fi option may also be available: select an authorized USB device and choose Enable Wi-Fi. This uses legacy ADB TCP mode on port 5555. Use it only on a trusted private network; disconnecting from iMirror does not disable that device-side listener.

Network safety: ADB over Wi-Fi provides powerful device access. Do not expose its port to the public internet or use an untrusted network. Return the device to USB mode when finished with legacy TCP mode.

Mirror controls and text

  • Click the mirrored preview to focus it. Click or drag to tap and swipe.
  • Scroll over the preview with a mouse wheel or trackpad.
  • Use the toolbar's Back, Home, and Recents buttons to navigate Android.
  • Press Command-V to send plain text from the Mac clipboard to the focused Android field. Pasting replaces the Android clipboard; avoid sending secrets to a device you do not trust.

Save screenshots and recordings

  • Choose the camera button or press ⌘S to save a PNG screenshot.
  • Choose Record or press ⇧⌘R to start or stop an MP4 recording.
  • Select a destination in the save dialog. Use Show in Finder to locate the latest capture.

Captures contain the Android display, not the Mac window chrome. Recordings contain video only and do not include audio. A recording is finalized when stopped, disconnected, or interrupted by a display-size change.

Troubleshooting

Device does not appear

Unlock the phone, reconnect the cable, confirm USB debugging is enabled, accept the trust prompt, then use Refresh. Try another data-capable USB cable or port if needed.

Device shows as unauthorized

Check the Android screen for the USB debugging authorization dialog. If the prompt does not return, revoke USB debugging authorizations in Android Developer options, reconnect, and approve the new prompt.

Wi-Fi pairing or connection fails

Confirm both devices share a network, use the pairing address only for pairing and the main Wireless debugging address for connecting, and re-pair if Android's address or port changed. Some guest networks isolate devices from one another.

Connection is slow or stalls

Move both devices closer to the Wi-Fi access point, avoid congested guest networks, or switch to USB. If the first frame does not arrive, reconnect the device.

Some Android content is black

Android may intentionally protect secure or DRM content from screen capture. iMirror cannot bypass those protections.

Still stuck? Email support@ourappsworld.com with your Mac model, macOS version, Android model/version, and connection type. Do not include private screen recordings unless you intend to share them.
